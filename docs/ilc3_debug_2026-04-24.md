# ILC3 디버깅 작업 정리 — 2026-04-24

## 목표
TX→RX PMOD 링크에서 RX가 프리앰블 `AA550800`을 복원하지 못하는 원인 추적.
OK/NG 카운트가 압도적으로 NG 상태.

  - RX: `localhost:3121/xilinx_tcf/Digilent/210351BE5D1FA` (COM9)

## ILC3 프로토콜 요약

| 심벌 | 진폭 페어 |
|------|-----------|
| 0    | [-1,  0]  |
| 1    | [ 0, -1]  |
| 2    | [+1,  0]  |
| 3    | [ 0, +1]  |

- 심벌당 2샘플, HOLD_N=20 클럭(160ns), GAP_N=4 클럭(32ns)
- 프레임: `[AA][55][08][SEQ×4][DE][AD][BE][EF][CRC8]` = 12바이트 = 48심벌 = 96샘플
- AA 바이트 = `10 10 10 10` (4×sym2) → 진폭 시퀀스: `+1, 0, +1, 0, +1, 0, +1, 0`

## 단계별 디버깅 진행

### Step 1 — 타이밍 스윕 (이전 세션)
VALID_DELAY / FRAME_DELAY 5가지 조합 테스트.  
**결과**: 어떤 조합도 `AA550800` 복원 안 됨. 타이밍만의 문제 아님.

---

### Step 2 — TX/RX 심벌 비교
TX UART: `S=AA550808` → TX 패킷 생성은 정상.  
RX UART: `S=A010....` → RX 심벌 복원 단계에서 이미 오류.

**결론**: TX 패킷 생성 로직은 정상. 문제는 물리 전송 또는 RX 수신 단계.

---

### Step 3 — RX 원시 진폭 덤프 (A= 단일 채널)
RX UART 형식 변경: `RX OK=... NG=... A=XXXXXXXX`

**결과**: `A=11110000` (일관됨)  
**기대값**: `10101010` (AA 바이트 = +1,0 교번)

| 위치 | 값 | 의미 |
|------|-----|------|
| 기대 | `10101010` | sym2×4 = (+1,0)×4 |
| 실측 | `11110000` | +1 4개 → 0 4개 연속 |

**결론**: 심벌 디코더 이전, 원시 진폭 캡처 단계에서 이미 패턴이 틀림.

---

### Step 4 — 3탭 비교 (A1/A2/A3)

RX UART 형식 변경: `RX OK=... NG=... A1=XXXXXXXX A2=XXXXXXXX A3=XXXXXXXX`

각 탭 정의:
- `amp_pulse_d1` = av_s2 상승엣지 (가장 이른 캡처)
- `amp_pulse_d2` = av_s3 상승엣지 (1클럭 지연)
- `amp_pulse_d3` = av_s4 상승엣지 (2클럭 지연)

**실측 결과**:
```
A1=1110000F  A2=11110000  A3=11110000
```

| 탭 | 값 | 분석 |
|----|-----|------|
| D1 | `1110000F` | 마지막 바이트=0xF(=-1), 전환 중 캡처 → 불안정 |
| D2 | `11110000` | 안정적 |
| D3 | `11110000` | D2와 동일 |

**핵심 발견**: 탭 선택과 무관하게 `11110000` 패턴. +1이 4개 연속 후 0이 4개 연속.  
**결론**: 탭 타이밍 문제가 아님. TX가 실제로 무엇을 출력하는지 직접 확인 필요.

---

### Step 5 — TX 진폭 덤프 추가 (오늘 구현)

#### top_ilc3_tx_board.v 수정 내용

1. TX 진폭 캡처 레지스터 추가:
   ```verilog
   reg [31:0] tx_amp_dbg_acc;
   reg [31:0] tx_last_amps;
   ```

2. PMOD FSM PH_IDLE 내 `amp_out_valid_w` 타이밍에 첫 8개 진폭 누적:
   ```verilog
   if (amp_cnt < 7'd8) begin
       if (amp_cnt == 7'd0)
           tx_amp_dbg_acc <= {28'd0, amp_out_w[3:0]};
       else
           tx_amp_dbg_acc <= {tx_amp_dbg_acc[27:0], amp_out_w[3:0]};
       if (amp_cnt == 7'd7)
           tx_last_amps <= {tx_amp_dbg_acc[27:0], amp_out_w[3:0]};
   end
   ```

3. UART 출력 형식 변경:
   ```
   TX PKT=XXXXXXXX S=XXXXXXXX A=XXXXXXXX\r\n
   ```
   (`A=` = TX가 PMOD에 실제로 출력한 첫 8개 진폭값)

#### 빌드 및 프로그래밍
- TX 빌드: `build_ilc3_tx_impl_tmp.tcl` → 성공 (`top_ilc3_tx_board.bit` 생성)
- TX 보드 프로그래밍: `program_tx_board.tcl` → 성공 (10:38:32)

## 현재 상태 (세션 종료 시점)

TX 보드에 새 비트스트림 프로그래밍 완료. TX UART 출력 확인 대기 중.

**다음 확인 사항**: TX COM8에서 `A=` 값 확인

| TX A= | 의미 | 다음 액션 |
|-------|------|-----------|
| `10101010` | TX 출력 정상 → PMOD 물리 배선 문제 | 핀 배선 점검 |
| `11110000` | TX 자체가 잘못된 패턴 | TX RTL(tx_core 또는 PMOD FSM) 버그 수정 |
| 기타 값 | 캡처 타이밍 문제 | amp_cnt 카운터 로직 재검토 |
